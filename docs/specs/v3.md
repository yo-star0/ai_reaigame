# v3 仕様書（作り込みラウンド・1週間版）

最終更新: 2026-04-19

## 1. 目的と背景

MVP+公開URLまで完成した状態で、恋愛シミュレーションゲームとしての**遊びの幅**を広げる。YAMLエンジン案から方針変更し、**DB管理＋管理画面**で運用者目線の仕組みを入れる。求人アピールとして「認証付きCRUD管理画面」「シナリオDB設計」「ロール制御」を追加で示せる。

## 2. 追加するユーザーストーリー

| ID | Who | What | Why |
| --- | --- | --- | --- |

## 3. データモデル（Prisma 追加分）

```prisma
model Scenario {
  id              String   @id @default(cuid())
  slug            String   @unique        // "hana-rainy-day"
  characterId     String
  title           String
  synopsis        String
  unlockAffinity  Int      @default(0)
  published       Boolean  @default(false)
  order           Int      @default(0)    // 一覧表示順
  createdAt       DateTime @default(now())
  updatedAt       DateTime @updatedAt

  character       Character @relation(fields: [characterId], references: [id], onDelete: Cascade)
  scenes          Scene[]
  progress        ScenarioProgress[]
}

model Scene {
  id          String   @id @default(cuid())
  scenarioId  String
  key         String                        // シーン内でユニーク、例 "open" "ask" "like"
  kind        String                        // "text" | "choice" | "end"
  body        String                        // ナレーションまたは質問文
  nextKey     String?                       // kind=text のみ
  order       Int      @default(0)

  scenario    Scenario @relation(fields: [scenarioId], references: [id], onDelete: Cascade)
  choices     Choice[]

  @@unique([scenarioId, key])
}

model Choice {
  id              String   @id @default(cuid())
  sceneId         String
  label           String
  affinityDelta   Int      @default(0)
  nextKey         String                    // 遷移先Scene.key
  order           Int      @default(0)

  scene           Scene    @relation(fields: [sceneId], references: [id], onDelete: Cascade)
}

model ScenarioProgress {
  id            String   @id @default(cuid())
  userId        String
  scenarioId    String
  completedAt   DateTime?
  lastSceneKey  String?
  createdAt     DateTime @default(now())
  updatedAt     DateTime @updatedAt

  user          User     @relation(fields: [userId], references: [id], onDelete: Cascade)
  scenario      Scenario @relation(fields: [scenarioId], references: [id], onDelete: Cascade)

  @@unique([userId, scenarioId])
}

// 既存User/Character/Conversation/Messageはそのまま
// Userに isAdmin フィールドを追加
model User {
  id          String  @id @default(cuid())
  firebaseUid String  @unique
  displayName String?
  isAdmin     Boolean @default(false)
  // 以下既存と同じ
}
```

## 4. API仕様（追加分）

### プレイヤー向け（要認証）

| メソッド | パス | 概要 |
| --- | --- | --- |
| GET | `/api/v1/characters/:id/scenarios` | キャラに紐づく公開済みシナリオ一覧（好感度でロック判定済み） |
| GET | `/api/v1/scenarios/:slug` | 詳細 + 全シーン + 選択肢 |
| POST | `/api/v1/scenarios/:slug/complete` | 完走を記録、好感度加算 |

### 管理者向け（`isAdmin=true` 必須）

| メソッド | パス | 概要 |
| --- | --- | --- |
| GET | `/api/v1/admin/scenarios` | 全シナリオ一覧（未公開含む） |
| POST | `/api/v1/admin/scenarios` | 新規作成（タイトル/slug/キャラ/解放条件） |
| GET | `/api/v1/admin/scenarios/:id` | 詳細 |
| PUT | `/api/v1/admin/scenarios/:id` | 更新 |
| DELETE | `/api/v1/admin/scenarios/:id` | 削除（論理削除は不要、hard delete） |
| PUT | `/api/v1/admin/scenarios/:id/scenes` | シーン一括置換（配列で送る） |

認可: `AdminGuard` を新設。`@CurrentAuth()` の firebaseUid で User を引いて `isAdmin=true` を要求。

DEVバイパス時: 環境変数 `DEV_ADMIN_UIDS` にカンマ区切り記載された uid はadmin扱い。

## 5. 画面（追加分）

### プレイヤー

- `/characters/[id]` に「シナリオ一覧を見る」ボタン追加
- `/characters/[id]/scenarios` — カード一覧（未解放はグレーアウト）
- `/scenarios/[slug]` — シナリオ再生画面（text/choice/endの順次表示）

### 管理者

- `/admin` — シナリオ一覧、新規作成ボタン
- `/admin/scenarios/[id]` — 編集フォーム（タイトル/ slug / キャラ / 解放好感度 / 公開 / シーン配列）
- シーン配列は行ごとに `kind` 選択、`body`、選択肢リスト編集

## 6. 動的トーン切り替え

`ChatService.buildSystemPrompt` に追加:

```
関係フェーズ:
- affinity < 15: 敬語主体、少し距離をおいた話し方
- 15 ≤ affinity < 40: 敬語と砕けた話し方が混ざる、たまに冗談
- 40 ≤ affinity < 70: タメ口が増える、相手を下の名前で呼ぶ
- 70 ≤: 親密、呼び捨てとあだ名、感情表現豊か
```

## 7. 非機能

- Admin画面はExpo Webのみ表示（ネイティブでは隠す）
- Firebase未設定時は `DEV_ADMIN_UIDS=demo-user` でdemo-userが管理者扱い
- シナリオ編集時の楽観ロックは不要（デモスコープのため）
