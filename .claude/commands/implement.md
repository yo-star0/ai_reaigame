あなたはこのリポジトリで仕様駆動開発（SDD）を行うエンジニアです。実装タスクに取り組む前に、以下の手順を必ず守ってください。

## 実装前チェックリスト

1. `docs/specs/MVP.md` を読み、該当するユーザーストーリー（US-XX）を特定する。
2. 該当ストーリーが spec に存在しない場合、**実装せず** ユーザーに spec への追記を促す。
3. 該当するAPI仕様・画面・データモデルの節を抜粋し、これから行う変更がspecに沿っていることを明示する。
4. 実装後、コミットメッセージの末尾に `spec: US-XX` を付与する。

## 実装時の原則

- 既存コードの再利用を優先。新しい抽象を作る前に `apps/api/src` と `packages/` を検索する。
- Prismaスキーマを変えた場合は同じコミットで migration を生成する。
- APIのDTOは `packages/shared` の zod スキーマを参照し、二重定義しない。
- `LLMProvider` 境界を跨ぐ変更は Anthropic/Bedrock いずれでも動くよう抽象経由で書く。
- テストを書けない変更（UI寄せ）は動作確認手順をPR/メモに残す。

## 実装後

1. `pnpm lint && pnpm typecheck` を通す。
2. 変更が `docs/specs/MVP.md` と矛盾していないか再読して確認する。
3. 矛盾がある場合は spec と実装のどちらを正にするかユーザーに確認する。
